# airportiq — Airport Investment Intelligence Agent

A conversational agent that helps an airport-modernization investor see which US airports are under the most
capacity pressure: where added runway, gate or terminal capacity would be absorbed. Every number comes from
deterministic code over public FAA and BTS data; the LLM interprets the question, calls typed tools and explains
the result inside an enforced JSON schema.

Design: [docs/DESIGN.md](docs/DESIGN.md) (architecture, scoring methodology with a worked SFO example, key tradeoffs, where AI is used).
Acceptance pass with evidence: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).
Product docs and specs: [agent-os/](agent-os/). Built 1.11.2026 as a one-day take-home.

## Run it

Requires Python 3.12 and [uv](https://docs.astral.sh/uv/).

```bash
uv sync
uv run agent chat --test "What can you help me with?"   # offline, no key, no spend
uv run agent serve --test                                # http://localhost:8000
```

With real models, copy `.env.example` to `.env` and set the keys you have (`ANTHROPIC_API_KEY` recommended;
`GOOGLE_API_KEY`, `TYPESAFE_API_KEY`, `OPENROUTER_API_KEY` optional). A model whose key is missing is skipped at
startup. Then:

```bash
uv run agent serve                       # chat page at /, API at /api/chat, docs at /api/docs
uv run agent eval --repeat 3 --tag latest
uv run agent eval --down anthropic --tag anthropic-outage   # proves cross-vendor fallback
```

Tests and lint (offline, no keys):

```bash
uv run ruff check src tests
uv run pytest -q
```

## Platform (v0)

- **Model chain:** `anthropic:claude-sonnet-5-5` → `anthropic:claude-haiku-5-5` → `google-gla:gemini-2.5-flash`
  through Pydantic AI's `FallbackModel`; per-model HTTP retries on 429/5xx/network with Retry-After; vendor SDK
  retries off. All models down → `status: unavailable`.
- **Guard:** regex layer → fixed intro for greetings → TypeSafe Jev screening (confidence ≥ 0.7, else Claude Haiku)
  with the previous question as context → fixed refusal strings. Refusals spend nothing.
- **Budget:** SQLite ledger enforces `BUDGET_USD` (10) per month before every paid call; 0.25 USD and 16 model
  requests per turn; 20 requests per IP per hour, 200 per day.
- **API:** `GET /health`, `POST /api/chat`, `DELETE /api/sessions/{id}`, `GET /api/stats` (admin token), chat page at `/`.
  Sessions in memory, 1 h TTL, LRU 500.
- **Evals:** `agent eval --repeat N --tag T --down <vendor> --model <id>`; reports under `evals/results/`; exit
  0 pass / 1 fail / 2 flaky; every number in an answer must appear in that turn's tool outputs.
- **Prompt caching** of the static prefix is on from the first commit; cache tokens are in every turn record.
- **Offline mode:** `MODEL_MODE=test` (or `--test`) runs everything on Pydantic AI's `TestModel`.
- **OpenSky (bonus, v6):** `aircraft_now` answers "how many planes are around SFO right now" from OpenSky's live state
  vectors; credentials are optional (`OPENSKY_CLIENT_ID` / `OPENSKY_CLIENT_SECRET`). Prompt 0.4.0 adds only the tool
  line; the live baseline was not re-run for it (about 8.3 USD of the monthly cap was spent on evals), the offline smoke
  set asserts the tool and a live query returned 17 aircraft around SFO on 1.11.2026.
- **Voice (bonus):** the chat page has a mic button (browser speech recognition, hidden when unsupported) and a
  read-aloud toggle (speech synthesis) using the Web Speech API only; nothing but text reaches the server.

## Data

- **Registry:** `config/airports.yaml`, generated by `agent registry` from the FAA TAF airport table (universe = the
  144 FAA large, medium and small hub airports, FAA annual service volume, coordinates), the FAA CY2025 enplanement
  file (hub class, boardings) and OurAirports (ICAO, runways). Census regions and divisions come from
  `config/areas.yaml`; name aliases ("LA", "John Wayne") from `config/aliases.yaml`.
- **Snapshot:** `data/snapshots/*.parquet` + `manifest.json`, written by `agent ingest` and committed, so a deploy
  needs no network and no hand-downloaded file:
  - `taf.parquet`: FAA Terminal Area Forecast 2025, operations and enplanements per airport and fiscal year,
    actual FY1976–FY2024 and forecast FY2025–FY2055, with the international enplanement split.
  - `ontime_monthly.parquet`: BTS Airline On-Time Performance 2023–2025 aggregated per origin and month
    (departures, cancellations, 15-minute delays, mean and 10th-percentile taxi-out). Domestic reporting carriers only.
  - `t100_annual.parquet`: BTS T-100 Segment (all carriers) 2023–2025 aggregated per origin, year, international,
    long-haul and cargo flag (departures, seats, passengers). T-100 has no scripted download: the three yearly
    CSVs were fetched once by hand through the TranStats form on 1.11.2026 and the manifest records the fields.
- **Capacity profiles:** `config/capacity_profiles.yaml`, extracted by `agent profiles` from the 31 FAA Airport
  Capacity Profile PDFs (2014–2019): hourly rates per weather condition.
- **Live:** FAA NAS status XML (closures, ground stops, delay programs), cached 10 minutes, and (v6) the OpenSky Network
  state vectors in a 25 km box around the airport (`aircraft_now`: total, airborne, on the ground, a few callsigns),
  cached 2 minutes, with the owner's registered client or anonymously under OpenSky's 400-credit daily limit. Both
  are shown beside the score and never blended into it.

```bash
uv run agent registry     # regenerate config/airports.yaml from data/raw
uv run agent ingest       # fetch the public sources into data/raw (gitignored) and rebuild data/snapshots
uv run agent profiles     # re-extract config/capacity_profiles.yaml
uv run agent score SFO    # print one airport's breakdown without a model call
```

## Scoring methodology (Capacity Pressure Score)

Every figure is computed by `src/app/scoring` from the snapshot; the LLM only chooses tools and explains.
`config/scoring.yaml` (version 1.0.0) holds every weight, threshold and definition.

| component | definition | source | weight |
|---|---|---|---|
| utilization | annual operations / annual capacity, latest three actual fiscal years | FAA TAF, capacity below | 0.3 |
| delay | mean of percentile(departures delayed 15+ min share) and percentile(mean taxi-out minus the airport's own 10th-percentile taxi-out) | BTS On-Time | 0.25 |
| growth | mean of percentile(FAA forecast 10-year enplanement CAGR from FY2024) and percentile(actual CAGR FY2019 to FY2024) | FAA TAF | 0.2 |
| load_factor | passengers / seats, scheduled passenger service | BTS T-100 | 0.15 |
| long_haul | departures of 3000+ statute miles / all departures (international share reported beside it) | BTS T-100 | 0.1 |

- **Normalization:** each component's latest-year value is percentile-ranked within the 144 hub airports (0–100,
  ties share a rank), so a value reads as "higher than N% of hub airports". **CPS** = Σ weight × percentile. When a
  component has no data for an airport the weights are renormalized over the others and the answer says so.
- **Lenses** map the brief's questions onto the components: `expansion` (the CPS), `congestion` (utilization,
  delay), `unmet_demand` (load factor, growth, delay), `long_haul`.
- **Capacity**, in order of precedence per airport (scoring 1.1.0): the FAA capacity-profile hourly rate
  (FAA-measured, 31 largest airports, 2014–2019) blended across weather conditions (visual 0.7, marginal 0.2,
  instrument 0.1) times 4000 hours-equivalent (the FAA service-volume rule of thumb); the FAA annual service
  volume from the TAF table (109 airports); a runway model fitted by least squares on the airports that have a
  service volume (RMSE 92,932 operations per year over 137 airports), reported as the uncertainty of every modelled
  capacity (3 airports: GPI, IWA, XNA; GUM has no runway data and reports capacity as unavailable). Every answer
  names the source. The profiles lead because the service volume is stale for the largest hubs (16 airports ran
  above it in FY2024, Denver at 1.96 times); 11 airports still run above their capacity figure and say so in
  `limitations`. SFO: profile 402,400 vs service volume 393,000.
- **Uncertainty:** per-year values over the window with min and max, trend = last year minus first year, the
  model RMSE, and `data_through` per source. COVID years 2020–2021 are never a trend or growth endpoint.
- **Not calibrated:** the weights express the investment reading of the brief (congestion first, growth second,
  traffic mix last). They are assumptions, versioned so any change is auditable, not fitted to realised outcomes.
- **On the committed snapshot** (`agent score`): SFO has CPS 74.3 (utilization 0.95 of 402,400 operations, load
  factor 0.823, 13.6% long-haul of 190,110 departures in 2025); ANC has 31.0% long-haul of 87,988 departures in
  2025 with cargo at 59% of movements; BOS leads New England on the expansion lens (77.1). The worked SFO example
  with every percentile is in [docs/DESIGN.md](docs/DESIGN.md) and is asserted by a test.

(Re-verified after the scoring 1.1.0 redeploy, commit `eee30c3`; the first record on the same day read 14610 ms, 0.0146 USD.)

`uv run agent accept https://airportiq.onrender.com` repeats the live acceptance pass (endpoints, the four brief
questions, follow-ups, guard layers) from `evals/accept/cases.yaml` and exits 0 only when every row passes; the
full evidence of the pass before submission is in [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).

Free-tier facts: the service sleeps after 15 minutes idle (30–60 s cold start on the next request); the disk is
ephemeral, so the SQLite spend ledger and in-memory sessions reset on redeploy; the provider-side caps below are
therefore the hard backstop. Production would use a persistent database for both.

## Spend limits

- Code: `BUDGET_USD` (15 USD per month, raised from 10 on 1.11.2026) enforced before every paid call (reserve → settle / release); 0.25 USD and
  16 model requests per turn; 20 requests per IP per hour, 200 per day. The guard's sub-cent screening call is not
  ledgered (known under-count, bounded by the per-day request cap); it is estimated per turn in `guard_cost_usd`.
  A reservation still open when the process exits is released, and reservations older than ten minutes left by a
  dead process are deleted at startup, so a crash leaves no orphaned rows; a call billed just before a crash is then
  not counted here, which is why the provider caps are the backstop.
- Provider consoles: Anthropic, Google and TypeSafe caps set by the owner on 1.11.2026 (2026-11-01) and raised to 15 USD the same day.
- Prices: `config/prices.yaml`, verified 2026-11-01.

## Assumptions, uncertainty, scoping

| Topic | What we assume or know | How the agent communicates it |
|---|---|---|
| Profitability | The score is a capacity-pressure proxy for where added capacity would be absorbed; construction cost, financing and revenue are out of scope | Stated in the intro, the footer and every `limitations` list |
| Weights and thresholds | Chosen to express the investment reading of the brief, versioned in `config/scoring.yaml`; not calibrated to realised outcomes | `scoring_version` in every result; first limitation on every score |
| Capacity | FAA profile rates for 31 airports (measured, dated 2014–2019); FAA service volume for 109 (a planning value, stale for the largest hubs); runway model for 3 (RMSE 92,932 ops/yr); GUM has none; 11 airports run above their figure | `capacity.source`, `uncertainty_operations` and an explicit limitation when operations exceed the figure; the answer must name the source |
| Capacity blend and hours | Profile rates blended visual 0.7 / marginal 0.2 / instrument 0.1 and converted with 4,000 hours-equivalent; both are planning heuristics | Config values; README; DESIGN |
| Delays | BTS On-Time covers domestic reporting carriers only; international and small operators are missing; years under 3,000 departures are dropped | Limitation on every score with a delay value |
| T-100 vintage | Downloaded by hand on 1.11.2026 through the TranStats form; the manifest records fields and date; refresh is manual | `data_through` per source; manifest; README data section |
| Growth | FAA's own forecast, not ours; actual CAGR runs FY2019→FY2024; 2020–2021 never used as endpoints | Growth detail carries both CAGRs and the years; COVID years listed in the data facts |
| Long haul | 3,000 statute miles or more (about six hours), all carriers including cargo; international share reported beside it | Tool note and the data facts; the answer names the year and the denominator |
| Universe | FAA large, medium and small hub airports (144); non-hub and non-US airports are out of scope | `NotFound` lists valid ids; refusal text names the scope |
| Normalization | Percentile rank within the universe; a component missing for an airport renormalizes the weights | Limitation names the missing components |
| Live status | FAA NAS status and OpenSky aircraft counts are "right now" signals shown beside the score, never blended; cached 10 and 2 minutes | Tool note; `available=false` with a reason on failure |
| Sessions and spend ledger | In memory and SQLite on an ephemeral disk; a restart forgets conversations and month-to-date spend; provider caps are the backstop | README deployment section |
| Platform provenance | The platform (chain, guard, ledger, evals) was lifted from an earlier project of the author; the data layer, KPI and prompts were built on 1.11.2026 | DESIGN key tradeoffs |
